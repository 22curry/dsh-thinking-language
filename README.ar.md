# dsh-thinking-language

اختر من إعدادات DSH اللغة التي تفكّر بها نماذج **DeepSeek Harness** — الصينية والإنجليزية والألمانية والفرنسية والإسبانية والبرتغالية واليابانية والكورية وغيرها.

الاختيار يخصّ الملف الشخصي (profile) لا المحادثة: الجلسات الجديدة ومساحات العمل الأخرى والوكلاء الفرعيون وإعادة التشغيل كلها تحتفظ به. اضبطه مرة واحدة.

---

## لماذا توجد هذه الإضافة

سلسلة تفكير النموذج يولّدها النموذج نفسه، وهو أيضًا يختار لغتها. المكان الوحيد الذي يمكن التأثير فيه على هذا القرار هو الطلب الذي يبدأ التفكير. تضيف الإضافة قسمًا قصيرًا إلى موجه النظام (system prompt) يحدد لغة التفكير، وبذلك يُكتب التفكير **بهذه اللغة من أول رمز (token)**:

- بلا طلب إضافي للنموذج، وبلا خدمة ترجمة، وبلا تأخير؛
- لا شيء يغادر جهازك؛
- الرد الظاهر يظل يتبع لغة المستخدم.

## التثبيت

**من واجهة DSH**

1. ضع هذا المجلد في أي مكان.
2. من الشريط الجانبي: **Plugins** → **Add plugin** → **Install a third-party plugin**.
3. الصق المسار المطلق للمجلد (مثل `C:\Users\you\dsh-thinking-language`) ثم ثبّته.
4. تظهر الحزمة في **Installed plugins** وتكون مفعّلة بعد التثبيت.

**من GitHub**

```bash
dsh plugin add github:22curry/dsh-thinking-language --profile <name>
```

في DSH Desktop الصق `github:22curry/dsh-thinking-language` في **Plugins → Add plugin** بدلًا من ذلك: تطبيق سطح المكتب يدير ملفه الشخصي بنفسه ولا تعمل عليه أداة CLI.

**من npm** (بعد النشر)

```bash
dsh plugin add dsh-thinking-language
```

## الاستخدام

افتح **الإعدادات** → **思考语言**، اختر لغة، انتهى.

نفس العنصر يظهر أيضًا في صفحة الحزمة داخل **Plugins**؛ كلاهما يقرأ ويكتب القيمة نفسها.

| الاختيار | الأثر |
| --- | --- |
| اتباع المحادثة (الافتراضي) | لا يُضاف شيء إلى الموجه، ويعمل النموذج كما كان. |
| `中文`, `English`, `日本語`, `한국어`, `Deutsch`, `Français`, `Español`, `Português`, `Italiano`, `Русский`, `العربية`, `हिन्दी`, `ไทย`, `Tiếng Việt`, `Türkçe`, `Bahasa Indonesia` | يفكّر النموذج بتلك اللغة. |
| لغة أخرى… | إدخال حر لما ليس في القائمة (مثل `Norwegian` أو `Cantonese`). |

تسري التغييرات عند الطلب التالي للنموذج، دون إعادة تشغيل.

## كيف يعمل

- جزء الـ Host يسجّل قسمًا في موجه النظام (`thinking-language`، الترتيب `10300`، الأخير في الموجه المجمّع) يحتوي تعليمات من سطرين. عند اختيار *اتباع المحادثة* يكون النص فارغًا ويختفي القسم، فلا يكلّف الافتراضي شيئًا.
- الاختيار هو إعداد الإضافة نفسها (`thinking-language` في patch الملف الشخصي). الحقل volatile: الكتابة تسري فورًا والطلب التالي يقرأ القيمة الجديدة.
- جزء المتصفح يرسم نقطتي الدخول عبر خدمة نماذج الإعدادات المشتركة، وكلاهما يكتب عبر مستند إعدادات الـ Host. لذلك تبقى القيمة بعد إعادة التشغيل وتُشارك بين كل الجلسات.

## الخصوصية والتكلفة

لا وصول إلى الشبكة، ولا قياسات، ولا بيانات اعتماد. تكلّف التعليمات نحو 50 رمزًا لكل طلب **فقط عندما تكون هناك لغة مختارة**؛ وفي الوضع الافتراضي لا تُرسل إطلاقًا.

## القيود

- تؤثر فقط على النماذج التي تُظهر تفكيرها.
- التعليمات يتبعها النموذج وليس harness — في المهام القصيرة جدًا قد يعود إلى لغة المحادثة.
- تغيير اللغة يغيّر بادئة موجه النظام، لذلك يُعاد بناء ذاكرة التخزين المؤقت للمزوّد مرة واحدة من تلك النقطة.
- التفكير المسجّل مسبقًا في الجلسات القديمة لا يُعاد كتابته ولا يُترجم.

## التطوير

```bash
node --check index.js
node --check client.js
```

ثبّت المجلد كما في الأعلى؛ مع HMR يُعاد تحميل جزء الـ Host في مكانه، وجزء المتصفح مع وحدة العميل التي يسجّلها.
