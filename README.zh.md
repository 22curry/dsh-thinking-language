# dsh-thinking-language

在 **DSH 设置**里选择模型思考（reasoning）时使用的语言——中文、英文、德语、法语、西班牙语、葡萄牙语、日语、韩语等等。

这个选择属于 profile，而不属于某个对话：新会话、其他工作区、子代理、重启之后都保持不变。设一次就够。

---

## 为什么需要它

模型的思考链是模型自己生成的，语言由它在生成时决定。能影响这个决定的唯一位置，就是发起思考的那次请求。这个插件往系统提示词里加一小段指令，告诉模型必须用哪种语言推理，于是思考**从第一个 token 起**就是目标语言：

- 不额外发请求、不调用翻译服务、没有延迟；
- 数据不出本机；
- 你看到的回答仍然跟随你说话的语言。

## 安装

**在 DSH 界面里**

1. 把这个文件夹放在磁盘任意位置。
2. 侧边栏打开 **Plugins（插件）** → **Add plugin** → **Install a third-party plugin**。
3. 粘贴这个文件夹的绝对路径（例如 `C:\Users\you\dsh-thinking-language`）并安装。
4. 安装后出现在 **Installed plugins** 列表里，默认已开启。

**从 npm 安装**（发布之后）

```bash
dsh plugin add dsh-thinking-language
```

## 使用

打开 **设置** → **思考语言**，选一个语言即可。

同一个控件也出现在 **Plugins** 里该插件的详情页上，两处读写的是同一个值，改哪个都行。

| 选项 | 效果 |
| --- | --- |
| 跟随对话（默认） | 完全不往提示词里加内容，模型行为和原来一样。 |
| `中文`、`English`、`日本語`、`한국어`、`Deutsch`、`Français`、`Español`、`Português`、`Italiano`、`Русский`、`العربية`、`हिन्दी`、`ไทย`、`Tiếng Việt`、`Türkçe`、`Bahasa Indonesia` | 模型用该语言思考。 |
| 其他语言… | 自由输入，覆盖清单外的语言（例如 `挪威语`、`粤语`）。 |

改完在下一个模型请求生效，不需要重启。

## 工作原理

- 宿主侧注册一段系统提示词（`thinking-language`，order `10300`，排在组装后提示词的最后），内容是一条两行的指令。选择“跟随对话”时文本为空，整段自动消失，所以默认状态零开销。
- 选择值就是本插件自己的配置项（profile patch 里的 `thinking-language`）。它是 volatile 字段：设置写入后原地更新，下一次请求就能读到新值。
- 浏览器侧用 DSH 共享的配置表单服务渲染两个入口，二者都通过宿主设置文档写入，所以重启不丢、所有会话共享。

## 隐私与开销

不联网、不收集遥测、不读写任何凭据。**只有在选了具体语言时**每次请求才会多出约 50 个 token；默认“跟随对话”完全不发送。

## 限制

- 它只影响会输出思考过程的模型；不暴露思考的模型不受影响。
- 指令由模型遵守，不是 harness 强制 —— 极短的任务偶尔可能滑回对话语言。
- 切换语言会改变系统提示词前缀，因此该会话的 provider 缓存会从改动处重建一次。
- 已经记录在旧会话里的思考不会被改写或翻译。

## 开发

```bash
node --check index.js
node --check client.js
```

按上面的方式把文件夹装上即可；开启 HMR 的 profile 会原地重载宿主侧，浏览器侧随它注册的 client 模块重载。
