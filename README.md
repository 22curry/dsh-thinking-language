# dsh-thinking-language

**English** | [中文](README.zh.md) | [日本語](README.ja.md) | [한국어](README.ko.md) | [Deutsch](README.de.md) | [Français](README.fr.md) | [Español](README.es.md) | [Português](README.pt.md)

Choose the language **DeepSeek Harness** models think in — Chinese, English, German, French, Spanish, Portuguese, Japanese, Korean, and more — from DSH Settings.

The choice belongs to the profile, not to a conversation: new Sessions, other workspaces, subagents, and restarts all keep it. Set it once.

---

## Why this exists

A model's chain of thought is generated by the model, in the language it decides to use. The only place that decision can be steered is the request that starts it. This plugin contributes one short system-prompt section naming the language the model must reason in, so the thinking is **written in that language from the first token**:

- no extra model request, no translation service, no latency;
- nothing leaves your machine;
- the visible reply still follows the language the user writes in.

## Install

**From the DSH UI**

1. Keep this folder anywhere on disk.
2. Open **Plugins** in the sidebar → **Add plugin** → **Install a third-party plugin**.
3. Paste the absolute path to this folder (for example `C:\Users\you\dsh-thinking-language`) and install.
4. The bundle appears under **Installed plugins** and is on after installation.

**From GitHub**

```bash
dsh plugin add github:22curry/dsh-thinking-language
```

In DSH Desktop, paste `github:22curry/dsh-thinking-language` into **Plugins → Add plugin** instead: the desktop application manages its own profile, so the CLI does not drive it.

**From npm** (once published)

```bash
dsh plugin add dsh-thinking-language
```

## Use

Open **Settings** → **思考语言** / **Thinking language**, pick a language, done.

The same control also appears on the bundle's page in **Plugins**, so it can be changed from either place; both read and write the same stored value.

| Choice | Effect |
| --- | --- |
| Follow the conversation (default) | Nothing is added to the prompt; the model behaves exactly as before. |
| `中文`, `English`, `日本語`, `한국어`, `Deutsch`, `Français`, `Español`, `Português`, `Italiano`, `Русский`, `العربية`, `हिन्दी`, `ไทย`, `Tiếng Việt`, `Türkçe`, `Bahasa Indonesia` | The model reasons in that language. |
| Other language… | Free text, for anything not listed (for example `Norwegian`, `Cantonese`). |

Changes take effect on the next model request; there is no restart.

## How it works

- The Host half registers one system-prompt section (`thinking-language`, order `10300`, the last section of the assembled prompt) whose text is a two-line instruction. When the choice is *follow* the text is empty and the section disappears, so the default costs nothing.
- The choice is this plugin's own configuration entry (`thinking-language` in the profile patch). It is a volatile field, so a settings write updates it in place and the next request reads the new value.
- The browser half renders the two entry points with the shared configuration-form service; both write through the Host settings document, which is why the value survives restarts and is shared by every Session.

## Privacy and cost

No network access, no telemetry, no credentials. The instruction is roughly 50 tokens per request **only while a language is selected**; with the default *follow* it is not sent at all.

## Limitations

- It steers models that expose their reasoning; a model without visible thinking is unaffected.
- The instruction is followed by the model, not enforced by the harness — very short tasks can occasionally slip back to the conversation language.
- Changing the language changes the system-prompt prefix, so the provider's cache is rebuilt from that point once per change.
- Already recorded reasoning in old Sessions is not rewritten or translated.

## Development

```bash
node --check index.js

```
